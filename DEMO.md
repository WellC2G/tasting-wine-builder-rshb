# Демонстрация «Конструктора дегустаций» v1.0.0

Практический сценарий показа на 10–15 минут: от запуска Docker-окружения до раскрытия образца, радиограммы и выгрузки в имитационный «Народный винный рейтинг».

## Что понадобится

- Docker Desktop с Docker Compose v2.
- Свободные порты `3000`, `4000`, `5432`.
- Для показа со смартфонов — ноутбук и 5–6 гостевых устройств в одной защищённой Wi-Fi сети организаторов.
- На гостевых устройствах должны быть отключены VPN и сторонние прокси: платформа блокирует такие подключения и повторный вход с одного IP.
- Для экспорта достаточно одной оценки; для демонстрации правила 2 сигм нужно не менее 5, лучше 6 оценок.

## 1. Запуск окружения

```bash
cp .env.example .env
docker compose up --build
```

Дождитесь состояния `healthy`:

```bash
docker compose ps
```

Сервисы:

| Сервис | Адрес |
| --- | --- |
| Клиент | <http://localhost:3000> |
| Swagger UI | <http://localhost:4000/api/docs> |
| API | <http://localhost:4000> |
| PostgreSQL | `localhost:5432` |

База при старте автоматически получает 5 миграций, 14 вин и учётную запись организатора из `HOST_EMAIL`/`HOST_PASSWORD`.

### Показ со смартфонов и планшетов

`localhost` на телефоне указывает на сам телефон. Чтобы открыть пульт и анкету гостя с мобильных устройств:

1. Узнайте IP ноутбука в локальной сети, например `192.168.0.105`.
2. Откройте на всех устройствах `http://192.168.0.105:3000`.

Клиент автоматически направит REST-запросы и Socket.io на `http://192.168.0.105:4000` — править `.env` и пересобирать образ не нужно даже при смене Wi-Fi сети. `NEXT_PUBLIC_API_URL` теперь служит только подсказкой порта API (по умолчанию `4000`); меняйте её вместе с `API_PORT` только если используете нестандартный порт.

QR-коды теперь строятся по LAN-адресу хоста, даже если пульт открыт на ноутбуке через `http://localhost:3000`. Полный адрес отображается под QR: он должен начинаться с `http://192.168.x.x:3000/...`, а не с `localhost`. Если Docker Desktop не смог определить адрес автоматически, нажмите «Указать LAN-адрес вручную» в окне QR или задайте `HOST_LAN_IP` в `.env`. Убедитесь, что брандмауэр ноутбука разрешает входящие подключения на порты `3000` и `4000`.

Перед показом отключите на гостевых устройствах VPN, iCloud Private Relay и сторонние прокси. Второй браузер или окно инкогнито на том же физическом устройстве блокируется с `409`, даже если у него другой `User-Agent`; перезагрузка страницы на уже зарегистрированном устройстве проходит штатно.

## 2. Вход организатора и создание дегустации

1. Откройте <http://localhost:3000/host/login>.
2. Поля входа пустые — демонстрационный блок и автозаполнение удалены. Используйте учётные данные из `.env`:

```text
HOST_EMAIL=sommelier@tasting.ru
HOST_PASSWORD=Sommelier2026!
HOST_NAME=Главный Сомелье
```

Пароль и имя можно изменить в `.env`; после перезапуска API учётная запись обновится автоматически.

3. Нажмите «Войти» — откроется дашборд `/host/events`.
4. Нажмите «Создать дегустацию» и заполните:
   - название, например «Слепая дегустация: Автохтоны России»;
   - режим `BLIND`;
   - шкалу `PARKER_100`;
   - 2–3 вина из каталога;
   - порядок образов, подписи «Образец №1», «Образец №2» и длительность 180 секунд.
5. Нажмите «Создать и открыть пульт».

## 3. Экран проектора

1. В карточке мероприятия нажмите «Экран» или откройте:

```text
http://localhost:3000/host/events/<ID>/screen
```

2. Выведите вкладку на проектор или телевизор, при необходимости включите полноэкранный режим браузера.
3. На экране уже видны название мероприятия, PIN-код, только гостевой QR-код для опоздавших и состояние текущего раунда. QR сомелье и токен организатора на проектор не выводятся.
4. После запуска раунда здесь появятся таймер, подпись «Образец №1» и прогресс полученных оценок.
5. После раскрытия — карточка вина, Parker-балл, категория, разбивка по критериям и Recharts-радар.

## 4. Мобильный пульт ведущего

1. На смартфоне или планшете откройте `http://<IP>:3000/host/events/<ID>/control` или нажмите «Пульт» в дашборде.
2. Нажмите «QR-код» и выберите вкладку:
   - «Для гостей» — показать гостям вход по PIN;
   - «Для сомелье (пульт)» — другой сомелье сканирует QR и попадает в этот пульт уже авторизованным, без email и пароля. Ссылка содержит JWT-токен `hostToken`, который автоматически очищается из адресной строки после входа.
3. Убедитесь, что счётчик обновляется: «В сети: N | Проголосовало: M».
4. Нажмите «Запустить раунд». На пульте и экране появится таймер.
5. Когда все проголосуют, нажмите «Остановить голосование».
6. Нажмите «Раскрыть карту» — образец и статистика синхронно откроются на всех устройствах.
7. Вернитесь к раскрытому раунду в списке: вместо таймера появится «Статистика раунда» с вином, средним баллом, категорией, критериями, радаром и дескрипторами.
8. Кнопка «Показать статистику» повторно рассылает статистику на проектор и телефоны гостей; «Перезапустить голосование» открывает раунд заново.

> Вкладка «Для сомелье (пульт)» предназначена только для ведущего и сомелье. Не выводите её на проектор: на экране `/screen` всегда отображается только гостевой QR.

> Если гость ещё не отправил оценку до блокировки, сервер вернёт `423`, а интерфейс гостя перейдёт в состояние «Приём оценок закрыт».

## 5. Гость: анкета и синхронное раскрытие

1. Гость сканирует QR-код или вручную открывает:

```text
http://<IP>:3000/join/<PIN>
```

2. Вводит имя, например «Алексей (Стол №3)», и нажимает «Войти в дегустацию».
3. До запуска раунда отображается «Ожидание запуска раунда сомелье…».
4. После старта гость видит базовые 50 баллов и четыре ползунка:
   - цвет и прозрачность `0..5`;
   - аромат `0..15`;
   - вкус и послевкусие `0..20`;
   - потенциал `0..10`.
5. Настраивает органолептику `1..10`, выбирает ароматические дескрипторы и добавляет заметки. Черновик автоматически сохраняется для раунда.
6. Нажимает «Отправить оценку» и видит сообщение «Ваш голос принят!».
7. Если ведущий перезапустил голосование, форма открывается с сохранёнными значениями; кнопка «Изменить оценку» позволяет отправить обновлённую оценку.
8. При раскрытии карточки гость видит вино, среднюю оценку, категорию, профиль и собственную оценку.

Для дополнительного вау-эффекта предложите пяти гостям поставить оценки около `90–94`, а шестому — демонстративно низкую `50–60`. Это позволит наглядно показать отсечение выбросов.

## 6. 2 сигмы, радиограмма и экспорт

### Фильтрация выбросов

Правило активируется при `N ≥ 5`. После нажатия «Раскрыть карту» сервер пересчитывает статистику:

- оценки вне `[μ − 2σ, μ + 2σ]` получают `is_outlier = true`;
- средний балл и категория считаются только по валидным оценкам;
- на экране проектора и у гостя отображается число валидных оценок и отфильтрованных выбросов;
- радиограмма строится по средним значениям сладости, кислотности, танинов, тела и интенсивности аромата.

Если гостевых устройств меньше 5, фильтрация не применяется — это корректное поведение, зафиксированное в спецификации.

### Выгрузка в «Народный винный рейтинг»

1. На пульте ведущего нажмите «Выгрузить в Народный рейтинг».
2. Сервер заново применяет фильтрацию 2 сигм, формирует OpenAPI-пакет и отправляет его на `PEOPLES_RATING_WEBHOOK_URL`.
3. В модальном окне появятся:
   - статус `MOCK_SUCCESS`;
   - квитанция вида `pr_mock_<uuid>_accepted`;
   - число валидных оценок и выбросов;
   - полный JSON-пакет.
4. Нажмите «Скачать JSON», чтобы скачать пакет.
5. Мероприятие переходит в статус «Экспортировано».

Проверить историю выгрузок можно в Swagger UI:

```text
GET /api/v1/events/{eventId}/export-logs
```

Полный снимок пакета сохраняется в таблице `export_logs`.

## Быстрая проверка API

```bash
curl http://localhost:4000/api/v1/health

# Имитационный приёмник доступен в Swagger:
# POST /api/v1/mock/peoples-rating/batch
```

Невалидный JSON на mock-эндпоинт возвращает `400`, демонстрируя валидацию OpenAPI-контракта.

## Полезные команды

```bash
docker compose logs -f api        # логи API и сокетов
docker compose logs -f client     # логи Next.js
docker compose down               # остановить, сохранить данные
docker compose down -v            # остановить и сбросить БД
```

## Чек-лист демонстрации

- [ ] Стек запущен, все три контейнера здоровы.
- [ ] Вход сомелье выполнен.
- [ ] Дегустация создана, экран проектора открыт.
- [ ] Гостевой QR содержит `http://<LAN_IP>:3000/...`, а не `localhost`.
- [ ] Гости подключились по QR/PIN.
- [ ] Второй браузер или инкогнито на том же устройстве получает `409`.
- [ ] Включение VPN или смена IP дают `403`.
- [ ] QR сомелье открывает пульт на другом устройстве без пароля и очищает `hostToken` из URL.
- [ ] На экране проектора нет QR сомелье и токена организатора.
- [ ] Раунд запущен, оценки поступают, счётчик растёт.
- [ ] Голосование закрыто, карточка и статистика раскрыты синхронно.
- [ ] Возврат к раскрытому раунду показывает статистику, а «Показать статистику» обновляет экран и гостей.
- [ ] Перезапуск раунда сохраняет черновик формы гостя и позволяет изменить оценку.
- [ ] Вино, Parker-балл, число голосов и радиограмма видны на проекторе.
- [ ] На дашборде завершённая дегустация выгружается кнопкой с модальным окном и JSON.
- [ ] Экспорт выполнен, квитанция и JSON скачаны.
- [ ] Статус мероприятия — «Экспортировано».
